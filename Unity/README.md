# Unity project

This is a native Unity project pinned to **Unity 6.3 LTS, 6000.3.25f1**. Unity's official release API lists 6000.3.25f1 as released on 2026-09-24 with revision `e1dba0a9aba4`; the editor release archive lists the same release. Install that exact editor and the Windows and/or Linux standalone build module through Unity Hub.

The manifest pins URP 17.3.0, Input System 1.20.0, uGUI 2.0.0, Test Framework 1.5.1, and glTFast 6.16.0. TextMesh Pro is included with uGUI 2.0.0, so no separate legacy TMP package is pinned. Unity engine modules for audio, IMGUI, physics, text rendering, and UI are pinned at 1.0.0. Unity's 6000.3 package reference maps URP 17.3 and Input System 1.20 to this Editor stream; Unity 6.3 uses Test Framework 1.5.1 (1.6.0 is for 6000.4). The remaining pins are compatible registry releases. The initializer enables both input backends so the legacy starter scripts continue to work during migration. The Boot scene redirects to Sanctuary Courtyard on Play and in a player build. The generated Courtyard scene contains only a root with the `SanctuarySlice` component; its runtime script creates the camera, lighting, environment, and HUD. On first initialization, the Editor imports uGUI's TMP Essential Resources if needed and adds URP, TMP SDF, and UI shaders to Graphics Settings so runtime-created materials survive player shader stripping. The first Editor open resolves transitive dependencies and creates `Packages/packages-lock.json`. That lockfile is intentionally generated by Package Manager rather than hand-authored.

Open `Unity/` as the project. On first Editor load, an idempotent initializer creates missing URP settings and the Sanctuary Courtyard scene, assigns Linear color and adds the project scenes to Build Settings. It preserves existing scene files and adds the `SanctuarySlice` component when its runtime type is available. It also imports the bundled TMP essentials when absent; if that import cannot complete, use **Window > TextMeshPro > Import TMP Essential Resources** and rerun initialization. The committed `Boot.unity` remains a minimal startup scene; the initializer attaches its loader and creates the playable Courtyard scene alongside it. Re-run from **Aegis > Initialize Project** after adding scripts or imported content. The slice currently uses procedural placeholder art; glTFast is available for importing the repository GLBs in later scene work.

Build from the Editor menu (**Aegis > Build > Windows x64** or **Linux x64**) or in batch mode:

```sh
/path/to/Unity -batchmode -quit -projectPath "$PWD/Unity" -executeMethod AegisFlorae.Editor.AegisBuildCommand.BuildWindows -logFile -
/path/to/Unity -batchmode -quit -projectPath "$PWD/Unity" -executeMethod AegisFlorae.Editor.AegisBuildCommand.BuildLinux -logFile -
```

The Boot scene loads Sanctuary Courtyard for Editor Play and player startup. Outputs go to `Unity/Builds/Windows/AegisFlorae.exe` and `Unity/Builds/Linux/AegisFlorae.x86_64`. Cross-builds require the matching Unity Build Support module. Batch commands require the Unity Editor and a valid Unity license. A Unity Editor is not installed in the authoring environment, so package resolution, scene generation, compilation, and player builds have not been run here.

## Run the slice

1. Add the repository's `Unity/` folder to Unity Hub and open it with the pinned Editor.
2. Let Package Manager finish. Run **Aegis > Initialize Project** if automatic initialization has not completed.
3. Open `Assets/Aegis/Scenes/SanctuaryCourtyard.unity` and press Play. The Boot scene is also a valid entry point after initialization.
4. Press **Q** or the Gatling button, then click beside the highlighted route to build. A tower costs 6 Scrap; invalid placement spends nothing. Call waves with **Space** or the wave button.

Controls: **WASD / arrows** pan, **wheel** zoom, **P** pause, **V** cycle 1×/2×/4×, **X** reclaim mode, **right-click / Esc** cancel placement. Reclaim a Gatling for 5 Scrap (the browser game's rounded 75% refund). HUD buttons provide restart and the same gameplay actions. This sample implements one tower role, Scouts/Drones, and three custom waves with base enemy stats; the 50-wave game, additional mechanics, gamepad, audio, and final external artwork remain future milestones. See [migration status](MIGRATION_STATUS.md).

## Verify

From the repository root, with a .NET 8 SDK installed:

```sh
dotnet run --project tests/unity-simulation/unity-simulation.csproj
python3 Unity/ArtPipeline/validate_manifest.py
```

The .NET harness compiles the actual production simulation source and currently passes 104 behavioral assertions. It does not exercise Unity presentation. Use **Window > General > Test Runner** to run the committed EditMode and PlayMode tests, or use the Editor CLI:

```sh
/path/to/Unity -batchmode -projectPath "$PWD/Unity" -runTests -testPlatform EditMode -testResults /tmp/aegis-editmode.xml -logFile /tmp/aegis-editmode.log
/path/to/Unity -batchmode -projectPath "$PWD/Unity" -runTests -testPlatform PlayMode -testResults /tmp/aegis-playmode.xml -logFile /tmp/aegis-playmode.log
```

Initialize the project before these runs. Unity tests and builds have not been executed in this workspace. After a successful Editor run, commit the resolved dependency lock, generated URP/project settings, and any imported required resource metadata so subsequent clean checkouts reproduce the same setup.
